# MILA web client

Mobile-first, voice-first UI for the MILA backend. One screen: consent, a big microphone
button, a text box, and the answer with tappable citations and a referral card.
Information + referral only; it never diagnoses, doses or interprets results.

Built with Next.js 14 (app router) and TypeScript. No UI framework, no web fonts, no images,
no analytics, no login. The only runtime dependencies are `next`, `react` and `react-dom`.

## Run

```bash
cd web
cp .env.example .env.local        # set NEXT_PUBLIC_API_BASE if the API is not on localhost:8000
npm ci
npm run dev                       # http://localhost:3000
```

The backend must allow this origin (`MILA_CORS_ORIGINS`, default `http://localhost:3000`).
Microphone access needs a secure context: `localhost` works, a phone on the LAN needs HTTPS
(or Chrome's `chrome://flags/#unsafely-treat-insecure-origin-as-secure` for testing).

`NEXT_PUBLIC_API_BASE` is inlined at build time. Leave it empty (`NEXT_PUBLIC_API_BASE=`) when a
reverse proxy serves `/api` next to the web app; the client then calls the same origin.

## Checks

```bash
npm run lint        # eslint (next/core-web-vitals)
npm run typecheck   # tsc --noEmit
npm test            # node:test, needs Node 22.18+ (runs .ts directly); the app itself runs on Node 20+
npm run build       # production build, standalone output
```

## Docker

```bash
docker build --build-arg NEXT_PUBLIC_API_BASE=https://api.example.org -t mila-web .
docker run --rm -p 3000:3000 mila-web
```

Multi-stage `node:20-alpine` image, non-root user, Next.js standalone server on port 3000.
Next.js build telemetry is disabled in the image (`NEXT_TELEMETRY_DISABLED=1`); set the same
variable locally if you prefer.

## Layout

| Path | Purpose |
|---|---|
| `app/page.tsx` | The single screen and its state machine (consent, ready, recording, transcribing, confirm, asking) |
| `app/layout.tsx`, `app/globals.css` | Document shell, CSS variables, 18px base font, 48px tap targets, reduced-motion rules |
| `components/ConsentDialog.tsx` | Language, under-18, region, consent text with Listen, "save my questions" (off by default), I agree |
| `components/MicButton.tsx` | Press to record, press again to stop; recording state and timer |
| `components/TranscriptConfirm.tsx` | "I heard: … Is this right?" with Yes / No / Edit |
| `components/AnswerView.tsx` | Sentences one per line with `[S1]` chips, confidence in words, translated note, demo badge, Listen, disclaimer, referral |
| `components/CitationSheet.tsx` | Bottom sheet with source title, section, version, date, page, review status |
| `components/ReferralCard.tsx` | Referral points with `tel:` call buttons |
| `components/EmergencyCard.tsx` | Red-flag outcome: emergency card, referral first, no answer text |
| `components/Footer.tsx` | Language switch, low-data mode, delete my data, long disclaimer |
| `lib/api.ts` | Typed client with AbortController timeouts (`/api/consent/text`, `/api/consent`, `/api/session/{id}`, `/api/transcribe`, `/api/speak`, `/api/ask`) |
| `lib/voice.ts` | MediaRecorder wrapper (`audio/webm;codecs=opus` with fallback) and a small audio player |
| `lib/storage.ts` | Safe localStorage wrappers; stores only the session id, lang, script, region, is_minor and display preferences |
| `lib/i18n.ts` | UI strings for sr, bs, me, hr, en; Serbian Cyrillic is generated by transliteration (digraphs first), mirroring the backend |
| `tests/` | `node:test` suites for i18n, storage and the API client |

## Behaviour notes

- Voice: press the mic to record, press again to stop (auto-stop at 60 s). The recording is
  uploaded to `/api/transcribe` and shown back as "I heard: …" before anything is asked. The
  browser blob is released right after upload. If `MediaRecorder` is missing the mic is hidden
  and typing still works.
- Audio: answers to voice questions play automatically unless low-data mode is on. The Listen
  button uses `audio_url` when the server attached one, otherwise it calls `/api/speak` with
  the `low_bandwidth` flag (8 kHz on the server).
- Low-data mode is remembered on the device. It turns off automatic playback and requests
  small audio.
- Outcomes: `answered` shows sentences with citation chips; `withheld` shows "I don't know
  this" plus the referral card; `redflag` shows a high-visibility emergency card with call
  buttons first and no answer text.
- Delete my data calls `DELETE /api/session/{id}` and then clears localStorage. If the server
  cannot be reached the user can retry or clear only this phone.
- Every request has a timeout (12 s for small calls, 45 s transcribe, 30 s speak, 60 s ask) and
  a clear retry control.
- A 403/404 from the API on an existing session sends the user back to the consent screen.

## Accessibility

18px base font, 48px minimum tap targets, visible focus rings, AA colour contrast, `aria-live`
regions for the recording state and the answer, `role="alert"` for errors and the emergency
card, Escape closes the citation sheet, and `prefers-reduced-motion` disables the pulse and
scroll animations.
